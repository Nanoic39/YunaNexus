# 签到提示无权限：CSRF 生命周期修复

## 问题与复现

用户端能够读取积分余额、流水，但点击签到返回 HTTP 403“无权限”。线上同一会话也出现登录操作短暂被拒绝。

根因位于认证服务的安全过滤链：无状态 JWT 在每个请求中重新认证，默认 `CsrfAuthenticationStrategy` 将其视作一次新的 Session 登录，清除了浏览器 CSRF Cookie。前端仍缓存着有效期内的掩码令牌，后续写请求的 Cookie 与请求头便不匹配。

旧生产验证脚本每次写请求都先重新引导 CSRF，掩盖了真实页面先读取账户信息、再使用缓存令牌提交的场景。这是原验收的覆盖缺口。

## 修复

在 `SecurityConfig` 的 CSRF 配置中显式使用 `NullAuthenticatedSessionStrategy`，避免 Bearer 每次认证时清除 CSRF Cookie。保留无状态会话配置、现有 CSRF 校验、JWT 校验、平台授权和签到仅限门户的业务限制。

没有给用户增加管理权限，没有将签到加入 CSRF 忽略列表。

## 回归

新增 `StatelessCsrfMvcTest`，通过真实 Spring Security 过滤链引导一次令牌，连续执行三轮已认证读取和写入，检查响应不清除 CSRF Cookie；缺失令牌、错误令牌仍必须返回 403。该测试在旧实现上准确失败。

本机生产构建通过：660 项测试，0 失败、0 错误，60 项 Redis/MySQL 依赖测试交由 CI 真实服务执行。GitHub Production CI/CD #39047229200 的测试打包与发布均成功。
