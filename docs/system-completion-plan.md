# 系统完善计划与验收记录

本计划以当前代码和生产联调为准，按顺序推进。历史审查报告和早期 roadmap 不代表当前缺陷清单。每阶段包含后端能力、前端对接、失败与越权测试、分类提交、生产验证；依赖外部服务的功能不伪造成功。

## 执行约束

- 后端 main、前端 master；不改分支，不合并全部改动为一个提交。
- 发布前扫描公开仓库内容；密钥仅留服务器私有配置。
- 服务器项目程序、数据、缓存、日志均留在 /YunaNexus；使用既有手动启动和发布轮询，无系统目录注册。
- 兼容性发布先后端、后前端，避免新页面请求尚未上线的接口。
- 仅使用专用测试账号和临时数据联调，完成后恢复账号并清理测试数据。

## 1. 数据正确性和核心通知流程（实施中）

已确认问题：站内信筛选仅作用于当前页；顶栏未读数来自第一页；“全部已读”只处理已加载记录且先乐观修改界面；重复已读请求报错；通知详情切换 ID 不重新加载；通知发送受众解析遇到用户角色查询失败时静默漏掉用户，超过扫描上限时静默截断。

本阶段验收：

- 服务端全量已读/未读筛选、全局计数、本人全部已读；只操作已送达站内信，不改变邮件、待发/失败记录或其他用户数据。
- 单条已读幂等；筛选、分页、顶栏和详情状态联动；请求失败有明确反馈，切换账号/页面不会显示迟到的旧数据。
- 不完整的受众查询必须中止，不发送部分名单；无效空选条件不扫描全体用户。
- 后端 HTTP 绑定、状态边界和所有权测试；前端异步竞态与受众失败测试；真实数据库/MQ之外的已送达测试夹具验证跨页操作。

## 2. 管理操作完整性与规模化

- 将按角色/权限解析通知受众下沉为受保护的后端批量查询，避免逐用户请求；预览名单与发送结果可核对，限制批量规模。
- 核对管理台每个菜单、操作按钮和后端角色/权限，完善默认菜单/权限绑定和系统角色保护。
- 对通知发送、应用审核、徽章发放、密码重置记录补充失败状态、筛选与审计，自动徽章仅在规则定义完整后开放。

## 3. 账号、授权与个人密钥

- 完整回归注册、邮箱绑定、自助重置、改密、会话撤销和账号锁定申诉。
- OAuth 授权详情明确数据范围、应用状态和撤销影响；密钥创建/撤销与作用域示例一致。
- 原密码保持 BCrypt 单向存储；管理员只查看授权的重置审计记录。
