# YunaNexus · 开发规范

> 全项目统一的开发规范。所有代码提交前必须满足本文档要求。

---

## 一、包结构

```text
cc.nanoic.yunanexus.{模块名}/
├── controller/       # REST 接口
├── service/          # 业务逻辑（接口 + impl 实现类）
├── mapper/           # MyBatis-Plus Mapper
├── entity/           # 数据库实体
├── domain/           # 领域对象（非数据库实体，如 VO/DTO/领域模型）
├── config/           # 配置类
├── handler/          # 异常处理、拦截器
├── filter/           # Servlet 过滤器（如 TraceIdFilter）
└── util/             # 工具类
```

## 二、命名规范

| 类型 | 规范 | 示例 |
| :--- | :--- | :--- |
| 类名 | 大驼峰 | `AuthUserService` |
| 方法名 | 小驼峰 | `getUserById` |
| 常量 | 全大写下划线 | `MAX_FAIL_COUNT` |
| 数据库表 | 小写下划线 | `auth_user` |
| 数据库字段 | 小写下划线 | `user_id` |
| Java 字段 | 小驼峰 | `shardIndex` |
| 请求头 | 连字符 | `X-Shard-Index` |
| 枚举 | 大驼峰 + 大写下划线 | `ErrorCode.SEGMENT_NOT_FOUND` |

> **数据权限列约定**（Phase A，配合 `common-data-scope`）：需要行级数据权限的业务表，统一使用 `dept_id bigint`（所属部门）与 `create_by bigint`（创建人）两列。`DataScopeInterceptor` 默认按此列名注入 `dept_id IN (...) OR create_by = ?`，可在 `@DataScope` 注解上覆盖列名。

> **分库分表列约定**（ADR-004 / ADR-013）：分片编号是**独立业务字段**，由业务方决策并落库（如 `auth_user.shard_index`、`file_meta.shard_index`），**不内嵌在内部 ID 中**。需要分片的业务表须持久化 `shard_index` 列，供路由复算与数据一致性校验（如 `fileId % 16` 与落库 `shard_index` 必须一致）。

## 三、统一响应格式

所有接口返回 `Result<T>`：

```json
{
  "code": 200,
  "msg": "操作成功",
  "tips": null,
  "data": {},
  "traceId": "0a1b2c3d...",
  "timestamp": 1789198086819
}
```

| 字段 | 说明 |
| :--- | :--- |
| `code` | 业务状态码，200 成功 |
| `msg` | 技术描述，给开发看 |
| `tips` | 友好提示，给用户看（可空） |
| `data` | 业务数据 |
| `traceId` | 链路追踪 ID，关联日志 |
| `timestamp` | 响应时间戳（毫秒） |

分页返回 `PageResult<T>`：

```json
{
  "code": 200,
  "data": {
    "records": [],
    "total": 0,
    "page": 1,
    "size": 20
  }
}
```

## 四、API 版本化与分页（ADR-017）

- **API 路径加版本**：`/api/v1/auth/login`、`/api/v1/segment/next`。
- **分页统一**：请求 `page`（从 1 起）+ `size`（默认 20，上限 100）；大数据量场景用游标式 `cursor` + `size`。
- **契约**：所有对外接口提供 OpenAPI 3.0 契约（请求/响应示例、字段类型、错误码），见 [api-contract.md](api-contract.md)。
- **参数命名**：根 pom 未启用 `-parameters` 编译参数，所有 `@PathVariable` / `@RequestParam` **必须显式指定名称**（如 `@PathVariable("fileId") long fileId`、`@RequestParam("status") int status`），否则运行期抛 `Name for argument of type [...] not specified`。

## 五、异常处理

- 业务异常抛 `BizException`，传入 `ErrorCode` 枚举。
- 全局异常处理器 `GlobalExceptionHandler` 统一捕获转 `Result`。
- **不要**在 Controller 里写 try-catch，交给全局处理器。
- 可预期异常用 warn，未预期错误用 error 并输出 traceId。

## 七、依赖规则（common 模块）

- `common-core`：**不能**引入任何 Web、数据库、Redis 等框架依赖，保持纯净。
- `common-web`：依赖 `common-core`，提供 Web 能力（异常、过滤器、错误码）。
- 业务模块**按需**引入，不要全量引入。
- 网关是 WebFlux 栈，**不能**引入 `common-web`，需自己写配置 Bean。

## 八、日志规范

- 使用 `@Slf4j`。
- 日志必须携带 `traceId`（通过 MDC 透传）。
- 异常日志打印完整堆栈，业务分支日志用 info/warn。
- **敏感信息脱敏**（ADR-018）：见下文「敏感信息脱敏」。

## 九、敏感信息脱敏（ADR-018）

| 字段 | 脱敏规则 |
| :--- | :--- |
| 手机号 | 保留前 3 后 4，中间 `****`（`138****5678`） |
| 邮箱 | 保留 @ 前 2 位（`ab****@xx.com`） |
| 身份证 | 保留首尾（`110***********1234`） |
| 银行卡 | 保留末 4 位 |
| 密码 / JWT / 密钥 | **永不输出** |

- **日志框架层**：Logback 自定义 Converter 统一脱敏。
- **接口响应层**：`auth_user` 响应不携带 `password` 字段；VO/DTO 层显式排除敏感字段。

## 十、安全规范

- 密码使用 BCrypt 存储。
- 密钥（AES/HMAC/masterIv/JWT 签名密钥）从 Secret/环境变量读取，**禁止硬编码**。
- 数据库密码从 Secret/环境变量读取。
- 对外接口一律返回外部 ID，内部 ID 永不暴露。
- 所有输入做校验（`@Valid`），禁止信任前端传参。
- CSRF：`SameSite=Lax/Strict` + 关键操作 CSRF Token。
- CORS：网关白名单 Origin，**禁用 `*`**。
- CSP：登录页配置 `Content-Security-Policy`。

## 十四、异步与状态机约定

- **状态用整型编码**：领域状态统一用 `int` 编码，并在字段 `COMMENT` 中列全部取值（如通知发送状态 `0-待发送 / 1-已发送 / 2-发送失败 / 3-已读`），不落地字符串枚举。
- **异步发送状态机**：生产者先落库「待发送」记录，再投递 MQ；消费者回查记录 → 执行真实投递 → 回写终态。以通知中心为例：`0 待发送 →（消费成功）1 已发送`、`→（消费失败）2 发送失败`（累加 `retry_count` 并截断 `error_msg`）；站内信被读取后 `1 → 3 已读`。
- **MQ 客户端**：不使用 starter 封装，直接使用原生 `org.apache.rocketmq:rocketmq-client`，由 `SmartLifecycle` 管理 producer / consumer 的启动与停机。
